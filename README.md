# Грузовые аукционы — SPA

Тестовое задание: SPA для работы с грузовыми аукционами по OpenAPI-схеме `openapi/openapi.auctions.v0.json`.

Бэкенда нет: все четыре операции контракта обслуживает MSW-мок с **изменяемым состоянием** — ставка действительно меняет текущую цену, места в рейтинге, торговый статус и продлевает время торгов.

## Запуск

```bash
npm ci
npm run dev
```

Приложение откроется на `http://localhost:5173` и сразу перенаправит на `/auctions`. Моки поднимаются автоматически до первого рендера, ничего дополнительно запускать не нужно.

Разработка велась на Node 24, минимально нужен Node 20 (Vite 8). Воркер MSW (`public/mockServiceWorker.js`) закоммичен, поэтому после `npm ci` дополнительных шагов вроде `msw init` не требуется.

## Что готово

- **Навигация** — шапка-таб с названием-ссылкой на список: подсвечена на самом списке, гаснет на вложенных экранах, сохраняется на экранах ошибок.
- **Список аукционов** — загрузка через TanStack Query, пагинация по `meta.last_page`, skeleton / empty / error, prefetch детальной по наведению.
- **Фильтры** — все одиннадцать обязательных позиций задания, синхронизация с URL, Zod-валидация с безопасными fallback, панель на десктопе и drawer с бейджем количества на телефоне.
- **Карточка** — номер заявки, тип и статус аукциона, торговый статус, маршрут, даты, груз, цена **с единицей измерения**, цена за км, шаг ставки, признак своей ставки, primary action.
- **Детальная страница** — организатор и контакты, все точки маршрута, груз и требования к ТС, условия оплаты, параметры торгов, min/max/step, состояние своей ставки, все четыре ограничения из DTO плюс два найденных в схеме сверх минимума; sticky-сайдбар с ценой, тумблером НДС и основным действием.
- **История ставок** — таблица на десктопе и карточки на мобильном, количество участников, цена с НДС / без НДС, перевозчик с ИНН, место в рейтинге, победитель, отменённая ставка с причиной, встречная ставка, переключатель «Показывать отменённые» (параметр `all`), empty state и состояние скрытой истории.
- **Форма ставки** — отдельный маршрут `/auctions/:uuid/bet` (открывается по ссылке), React Hook Form + Zod с границами из detail DTO, кнопки быстрого шага `±step`, подсказка по доступной цене и шагу, мутация с инвалидацией list/detail/bets, success/error toast, разбор 422 по полям. На десктопе — модалка, на мобильном — полноэкранная страница.
- **Моки MSW** — сид из 60 аукционов, покрывающий ветки интерфейса, серверная валидация ставки, ошибки 401/404/422/503.
- **Слой данных** — DTO генерируются из схемы (рукописных нет), типизированные ошибки, фабрики `queryOptions`, префиксная иерархия ключей.

## Что не готово

Все функциональные требования задания закрыты. Осознанно не сделано:

- расширенная секция фильтров «Ещё фильтры» — обязательный минимум задания закрыт полностью, дополнительные фильтры схемы в интерфейс не выведены;
- поля схемы, которых задание не требует и которые не выведены в интерфейс: `chat_id`, `send_deal_before_load` (`assembly` и `admitted_organizations` показываются на детальной);
- `form_type` и `replace_external_pads` — схема не даёт списка допустимых значений (см. таблицу решений ниже).

## Проверка

### Как я выбрал проверять

Три уровня, по убыванию надёжности — каждый закрывает то, что не видит предыдущий:

1. **Юнит-тесты чистых функций** (24 файла). Вся логика вынесена из компонентов в утилиты именно ради этого: разбор URL, сборка тела запроса, мапперы, схема валидации ставки проверяются без рендера. Писались **до** кода.
2. **Интеграционные поверх MSW** (8 файлов) — настоящий роутер и настоящий слой запросов, без моков внутри приложения. Проверяют то, чего не видит юнит-тест: связку «клиент → HTTP → мок → клиент», loader'ы маршрутов, инвалидацию кэша.
3. **Ручной прогон в браузере** — для того, чего не видит ни один автотест: вид, цвета, адаптив.

Плюс отдельный приём: **мутационная проверка** новых тестов — реализация намеренно ломается тем способом, от которого тест защищает, и прогон обязан покраснеть. Трижды это показало, что тест не проверяет ничего; такие тесты переписаны или удалены.

### Что проверяется только руками

Автотесты идут в jsdom и по построению не видят следующего — здесь нужен браузер:

- **вид и читаемость**: цвета, контраст, подсветка активного таба, зачёркнутая цена отменённой ставки;
- **адаптив на реальных ширинах** — 320/375/414/600/768/900/1280/1920, телефон в landscape, зум 200%;
- **модалка формы ставки на десктопе**: заглушка `matchMedia` в тестах не разбирает `max-height`, поэтому в jsdom всегда выбирается полноэкранная ветка;
- **sticky-поведение сайдбара** детальной при длинном списке точек маршрута.

Ручная проверка велась точечно и полным прогоном по всем брейкпоинтам **не закрыта** — это записано в ограничениях. Её польза при этом подтвердилась предметно: отсутствие сквозной навигации (с детальной было не вернуться к списку) нашлось именно открытием страницы в браузере. Ни ревью по диффу, ни сверка со списком требований этого не поймали — обе методики проверяют написанное, а не **не**написанное.

### Сценарии для ручного прохода

Ниже — маршрут проверяющего. Данные подготовлены в сиде: ссылки воспроизводимы, ничего настраивать не нужно.

### Список и фильтры

1. `/auctions` — двадцать карточек, счётчик «Найдено», пагинация внизу.
2. Наведите мышь на карточку — в ней появляется **шаг ставки**. Его нет в ответе списка: он подтягивается из detail, который греет prefetch. До наведения блока шага нет намеренно.
3. Включите «Только мои торги» — выдача сужается, фильтр появляется в адресной строке, страница сбрасывается на первую.
4. Скопируйте адрес с фильтрами в новую вкладку — состояние воспроизводится полностью.
5. `/auctions?page=abc&per_page=99999&status=МУСОР` — страница открывается с дефолтными фильтрами, без ошибок: `page` → 1, `per_page` → 100, неизвестный статус отброшен.
6. `/auctions?cargo_num=нет-такого` — пустое состояние с подсказкой про фильтры.
7. Сузьте окно до мобильной ширины — панель фильтров превращается в кнопку с бейджем количества активных фильтров и открывается снизу.

### Ошибки контракта

Аукционы-триггеры в сиде: ссылка воспроизводима, специальных действий не нужно.

- `/auctions/auction-401-unauthorized` — «Сессия истекла», **без** кнопки повтора: 401 повтором не лечится.
- `/auctions/auction-503-unavailable` — «Сервис недоступен» с кнопкой «Повторить».
- `/auctions/нет-такого-аукциона` — «Не найдено» со ссылкой на список: 404 в этом контракте ожидаемое состояние, а не сбой.

### Детальная страница и ставки

- `/auctions/auction-with-canceled-bets/bets` — аукцион с отменёнными ставками обоих видов (по флагу `is_rejected` и по непустой `cancel_reason`): приглушённая строка, зачёркнутая цена, причина отмены.
- Тумблер «Показывать отменённые» — выключите: запрос уходит с `all=false`, и отменённые ставки **пропадают из ответа мока**, а не скрываются на клиенте. Счётчик участников при этом не меняется — он считается по неотменённым в обоих режимах.
- `/auctions/auction-hidden-bets-history/bets` — скрытая история: ставки не запрашиваются вовсе (проверяется тестом по пустому кэшу, а не по отсутствию таблицы).
- Переключатель «с НДС / без НДС» в сайдбаре детальной — цены пересчитываются сквозным образом, включая историю ставок.

### Сквозной сценарий ставки

1. `/auctions/auction-biddable-prolonged` — аукцион на понижение, ставить можно.
2. «Сделать ставку» → форма открывается **по своему адресу** `/auctions/auction-biddable-prolonged/bet` (модалка на десктопе, полноэкранная страница на мобильном). Ссылку можно прислать — она откроется сразу в режиме ставки.
3. Введите цену **не ниже** текущей — форма отклонит её сама, запрос не уйдёт: аукцион на понижение.
4. Очистите поле — «Введите цену.»; введите цену не кратную шагу — сообщение с подстановкой чисел и единицы измерения.
5. Кнопки `−500 ₽` / `+500 ₽` меняют то же поле, что и ручной ввод.
6. Отправьте корректную ставку: toast «Ставка принята», возврат на детальную, **новая текущая цена**, «Моя ставка» заполнена, время торгов продлено на `prolong_after_bet`.
7. Вкладка ставок — своя ставка подсвечена и стоит на первом месте; в списке у карточки появился признак своей ставки и статус «Лидирую».
8. `/auctions/auction-not-biddable/bet` — экран ограничения вместо формы, с кнопкой назад.

## Архитектура

### Стек сверх обязательного

Задание фиксирует React, TypeScript, Vite, TanStack Router/Query, RHF + Zod, MSW, FSD и «MobX или Zustand». Остальное — выбор кандидата:

| Что           | Почему                                                                                                                                                                                             |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Zustand**   | Клиентского состояния здесь мало и оно точечное: режим НДС, открытость drawer'а фильтров, «моя личность». MobX потянул бы декораторы и `observer` ради трёх сторов без единой вычисляемой величины |
| **MUI**       | Готовая адаптивность (`Grid`, брейкпоинты), `DateTimePicker` для фильтров дат со смещением, доступность из коробки. Тема одна, магические числа в `sx` не разбросаны                               |
| **notistack** | Тосты успеха/ошибки для мутации ставки; React 19 поддерживается официально                                                                                                                         |
| **date-fns**  | Адаптер для пикеров MUI и работа со смещениями. Формат ответов схемы — naive-время без зоны, запросов — со смещением; это два разных хелпера, а не один                                            |

### Конвейер данных

Центральное правило, из которого следует почти вся структура:

```
OpenAPI JSON ──npm run generate──> generated/schema.ts ──> DTO (shared/api)
                                                            │
                                          mapper (чистая функция, JSDoc, тест)
                                                            ↓
                                                        ViewModel
                                                            ↓
                                                     Component (разметка)
```

Три запрета делают правило проверяемым: компонент **не** типизируется DTO; ViewModel **не** содержит опциональных полей (`required` объявлен у 6 схем из 48 — тотализация нужна на границе); маппер **не** знает о React и потому тестируется без рендера.

### Именование компонентов

Задание требует суффикс `*.component.tsx` для **всех** React-компонентов. В проекте их 54, все с суффиксом; проверяется грепом по `src` на `export const <Заглавная> = … =>` вне таких файлов.

Единственное исключение — **файлы маршрутов** в `src/routes`: их имена диктует file-based routing TanStack Router (`bet.tsx` даёт путь `/bet`, переименование в `bet.component.tsx` изменило бы URL). Поэтому из них вынесена вся разметка: `RootLayout` и `PlaceBetUnavailable` живут в своих `*.component.tsx`, а в маршруте остаётся конфигурация — `loader`, `validateSearch`, `errorComponent` и трёхстрочный адаптер, который читает параметры маршрута и передаёт их в компонент страницы. Ни одного элемента разметки, объявленного в файле без суффикса, не осталось.

### Слои FSD

```
src/
  app/        провайдеры, тема, роутер, bootstrap моков
  pages/      auctions-list, auction-detail, auction-bets, place-bet
  widgets/    auction-filters, auction-card-list, auction-summary, bets-table
  features/   filter-auctions, place-bet, prefetch-auction, vat-toggle
  entities/   auction, bet, organizer
  shared/     api (http, generated), ui, lib, config, model
```

Импорты только вниз, обращение к чужому слайсу — через его `index.ts`; правило сторожит ESLint, а не договорённость. Три стыка разрешены явно: стор режима НДС и «личности» живут в `shared/model`, потому что их читают компоненты `entities`; prefetch приходит в карточку пропом, потому что хук лежит в `features`; словарь городов — в `shared/config`, потому что нужен и приложению, и сиду моков.

Сущности одного уровня **не видят друг друга** — поэтому `entities/bet` объявляет свои типы цены, структурно совпадающие с типами `entities/auction`. Это следствие границы слоя, а не недосмотр; склейка происходит уровнем выше, в виджетах.

### Устройство моков

`src/mocks` — не набор фикстур, а **сервер с состоянием**. Одна каноническая сущность на аукцион; проекции списка и detail собираются из неё двумя явными мапперами, поэтому после ставки они не могут разъехаться. Мутатор пересчитывает места в рейтинге с учётом направления торгов, торговые статусы участников и продлевает `stop_time`. Валидация ставки — серверная (ограничение «> 0» задано только описанием поля в схеме), поэтому ветка 422 в форме достижима по-настоящему.

Мок читает словарь кодов статусов из прод-кода (соглашение «статус ↔ число» должно быть одно), но **даты считает сам** — формат ответа он обязан воспроизводить независимо, иначе тестовый дубль и проверяемый код начнут подтверждать друг друга.

## Генерация типов

Рукописных DTO в проекте нет. При изменении `openapi/openapi.auctions.v0.json`:

```bash
npm run generate
```

Типы пересоздаются целиком, руками их не правят. Сгенерированный `src/shared/api/generated/schema.ts` **закоммичен**, поэтому проверяющему запускать генерацию не нужно — `npm ci && npm run dev` достаточно. Импорт `generated/**` откуда-либо, кроме `shared/api`, запрещён линтером: сгенерированные типы не растекаются по коду, наружу смотрят короткие алиасы из `shared/api/dto.ts`.

Воспроизводимость проверяется командой `npm run generate && git diff --exit-code src/shared/api/generated` — она доказывает, что закоммиченные типы ровно те, что даёт схема.

## Принятые решения по неоднозначностям контракта

Схема в нескольких местах допускает разные трактовки. Выбор и обоснование каждого — в `OPENAPI_ANALYSIS.md`, здесь коротко:

| Развилка                                                            | Решение                                                                                                                                      |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| В какой базе НДС отправлять ставку — признака в `SetBetRequest` нет | Всегда **с НДС**: это база `current`/`min`/`max`/`step`. В режиме «без НДС» показывается пересчёт, но отправляется базовое значение          |
| `hide_bets_history` лежит в двух местах                             | История считается скрытой, если `true` хотя бы в одном                                                                                       |
| Что скрывает `hide_points_address_and_contacts`                     | Адреса и контакты **точек маршрута**; контакты организатора управляются непустотой `contacts[]`                                              |
| Количества участников в ответе нет                                  | Вычисляется как число уникальных `organization_id` среди неотменённых ставок                                                                 |
| Шаг ставки требуется в карточке, но в DTO списка отсутствует        | Берётся из кэша detail после prefetch; нет в кэше — блок не рендерится. N+1 запросов ради шага не делается                                   |
| `bid_measurement_type` = `null` или `Unknown`                       | Трактуется как `PerRoute` (цена за рейс)                                                                                                     |
| `all` у `GET /bets`                                                 | По умолчанию `true`, иначе признак и причина отмены недостижимы                                                                              |
| `statuses` описан как «1–7», а кодируемых значений восемь           | Отправляются коды 1–8                                                                                                                        |
| `form_type`, `replace_external_pads`                                | Сознательно не поддерживаются: допустимых значений схема не даёт                                                                             |
| Фильтры — URL или localStorage                                      | **URL**: ссылка воспроизводима, работает «назад», состояние переживает перезагрузку, и именно search params требуют Zod-валидации с fallback |

## Ограничения

Перечислены честно, включая то, что проверить не удалось.

- **Соответствие моков схеме держится на сгенерированных типах и внимании**, а не на контрактном тесте против самого JSON схемы. Это первый пункт в списке «что сделать за ещё один день».
- **Ветка модалки формы ставки (десктоп) не покрыта автотестом.** Заглушка `matchMedia` в тестах разбирает `min-width`/`max-width`, но не `max-height`, поэтому в jsdom всегда выбирается полноэкранная ветка. Проверялась вручную.
- **Адаптив проверялся брейкпоинтами в тестах и вручную**, автоматических скриншотных проверок нет.
- **Доступность** опирается на компоненты MUI; прогон axe и полная проверка клавиатурной навигации не делались.
- **Соответствие «статус аукциона ↔ числовой код» в схеме не описано** — это соглашение проекта, зафиксированное в одном словаре, который читают и клиент, и мок. Если бэкенд ждёт другой порядок, фильтр статусов молча вернёт не то.
- **«Моя личность» захардкожена** (`shared/model/current-user.store.ts`): эндпоинта профиля в схеме нет, поэтому `subscriber_id`/`organization_id` перевозчика фиксированы. От них зависит подсветка своей ставки.
- **Оптимистичных обновлений нет намеренно** — после ставки источник истины сервер: ответ `POST /bets` не имеет схемы, а пересчёт мест и статусов клиентом не воспроизводится.
